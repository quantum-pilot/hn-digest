# Ask HN: How can I get better at using AI for programming?

- Score: 175 | [HN](https://news.ycombinator.com/item?id=46255285) | Link: https://news.ycombinator.com/item?id=46255285

### TL;DR

A developer rebuilding a jQuery and Django application in SvelteKit wants AI output close enough to review in 15–20 minutes instead of spending one to two hours per route. The desired rewrite requires semantic markup, minimal Tailwind, composable components, Storybook coverage, preserved styling, and removal of design debt. The thread converged on treating the model less as an autonomous rewriter and more as a collaborator requiring explicit standards, examples, staged work, and feedback. Users reported unreliable instruction adherence and a gap between plausible code and maintainable code.

### Comment pulse

- Claude Code staff recommended CLAUDE.md, Plan mode, Opus 4.5, and browser automation for self-checking.
- Detailed voice prompts and explicit questions can reduce ambiguity — counterpoint: some readers found verbosity distracting and instructions still degraded over time.
- A search-oriented workflow favors small edits, immediate tests, alternate models, then manual work when repeated attempts fail.

### LLM perspective

- View: AI helps most when the developer turns taste into examples, constraints, and executable feedback.
- Impact: The migration can accelerate, but architectural judgment and acceptance criteria remain human bottlenecks.
- Watch next: Compare per-route review time, defect rates, and rework across models and planning workflows.
