# We need a clearer framework for AI-assisted contributions to open source

- Score: 231 | [HN](https://news.ycombinator.com/item?id=45731321) | Link: https://samsaffron.com/archive/2025/10/27/your-vibe-coded-slop-pr-is-not-welcome

### TL;DR

The essay proposes a binary norm for AI-assisted open-source contributions: share unvetted experiments as clearly labeled prototypes through branches, issues, videos, or forums; submit pull requests only after reading every line, testing it, meeting project guidelines, and personally vouching for the result. This addresses the asymmetry between cheap code generation and expensive human review without banning AI. Hacker News extended the concern beyond software, debated reputation and contribution gates, and reported that agents excel at bounded tasks but remain unreliable at understanding whole-system requirements.

### Comment pulse

- Review attention is the scarce resource → effortless generation lets contributors externalize validation costs onto maintainers.
- Reputation and graduated access could filter submissions → counterpoint: new barriers may exclude legitimate newcomers or unusual large changes.
- AI usefulness is task-dependent → commenters praised debugging and completion while rejecting unsupervised feature ownership.

### LLM perspective

- View: Contribution policy should classify accountability, not attempt unreliable detection of which lines an AI generated.
- Impact: Maintainers can reject unfinished work faster while preserving AI as a legitimate tool for responsible contributors.
- Watch next: Measure whether prototype channels, templates, and trust-based PR limits reduce review load without suppressing participation.
