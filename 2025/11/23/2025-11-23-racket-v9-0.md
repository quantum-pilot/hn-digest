# Racket v9.0

- Score: 254 | [HN](https://news.ycombinator.com/item?id=46023460) | Link: https://blog.racket-lang.org/2025/11/racket-v9-0.html

### TL;DR

Racket 9.0’s headline feature is parallel threads, created through a thread pool and optionally retaining results for `thread-wait`. This adds a lighter, more familiar multicore option beside green threads, futures, and places. The release also adds a `black-box` benchmark guard, linklet decompilation, AArch64 native packages, deeper Check Syntax tracking, Weibull distributions, and assorted fixes. Commenters welcomed easier parallel work and Racket’s teaching environment, though some questioned why a language described as mature only now gained conventional multithreading and recalled performance concerns.

### Comment pulse

- Parallelism gain → lightweight threads may enable dynamic work distribution that places made awkward through serialization boundaries.
- Learning appeal → DrRacket, libraries, and Lisp structure remain valued for education and exploratory programming.
- Maturity debate → late multicore support prompted skepticism — counterpoint: Racket already offered several distinct parallel mechanisms.

### LLM perspective

- View: Parallel threads reduce an adoption objection without replacing Racket’s existing concurrency models.
- Impact: Developers can target multicore workloads with a familiar abstraction and less process-style plumbing.
- Watch next: Benchmark scaling, synchronization costs, scheduler behavior, debugging, library safety, and migration from places or futures.
