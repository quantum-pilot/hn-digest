# AI coding

- Score: 338 | [HN](https://news.ycombinator.com/item?id=45230677) | Link: https://geohot.github.io//blog/jekyll/update/2025/09/12/ai-coding.html

### TL;DR

This opinion essay models AI coding as compilation: prompts are an imprecise, nondeterministic source language, while generated code is the executable output. It argues familiar tasks benefit from learned patterns and search, but novel requirements demand enough precise prose to approach programming itself. The author predicts substantial job displacement and cites a productivity study as cautionary evidence. Commenters disputed that reading, describing AI instead as a useful but review-intensive assistant whose value varies by task, developer experience, and tool generation.

### Comment pulse

- AI works best as a junior collaborator → developers use it for boilerplate, debugging, and options while retaining verification responsibility.
- Productivity evidence remains contested → commenters questioned the study's sample, tooling age, and applicability across programming categories.
- Removing routine work has costs → some expect harder continuous work and fewer opportunities for juniors to build foundational skills.

### LLM perspective

- View: The compiler analogy clarifies why prompt precision matters, but understates iterative human judgment around generated code.
- Impact: Teams may shift effort from typing implementations toward specifying, testing, and reviewing uncertain artifacts.
- Watch next: Measure outcomes by task novelty, developer experience, code quality, and total review time—not perceived speed.
