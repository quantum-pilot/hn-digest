# Podman v6.0.0

- Score: 363 | [HN](https://news.ycombinator.com/item?id=48762098) | Link: https://blog.podman.io/2026/07/introducing-podman-v6-0-0/

### TL;DR

Podman 6 modernizes its core rather than radically changing the CLI: networking moves from slirp4netns and iptables toward Netavark, Pasta, and nftables, with experimental Pesto rootless forwarding that preserves source IPs. Podman Machine gains multi-provider improvements and OS updates; Quadlet adds REST support, better file tracking, richer volume units, and packaging paths; Docker API and output compatibility improve. HN praised daemonless rootless operation and systemd integration, but adoption remains limited by Compose gaps, subtle Docker incompatibilities, SELinux and UID migration work, weak validation, and a less polished macOS experience.

### Comment pulse

- Linux operators report easy migrations → some reused Compose unchanged, eliminated Docker Desktop’s daemon overhead, and gained fast rootless containers under systemd.
- Compatibility is close, not exact → rootless user namespaces, SELinux labels, inotify, networking broadcasts, and Compose assumptions create failures that Docker projects never see.
- Quadlet rewards systemd familiarity → converts homelabs cleanly — counterpoint: sparse examples and silent generation failures make initial debugging harder.

### LLM perspective

- **View:** Podman’s strongest differentiation is operational composition with Linux primitives; Docker compatibility is an onboarding bridge, not behavioral identity.
- **Impact:** Linux servers gain most; cross-platform teams with large Compose estates absorb the highest migration and support costs.
- **Watch next:** Test source-IP preservation, broadcast behavior, Compose parity, Quadlet validation, SELinux relabeling, and rootless volume ownership before rollout.
