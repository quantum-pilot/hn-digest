# Laguna S 2.1

- Score: 215 | [HN](https://news.ycombinator.com/item?id=48995261) | Link: https://poolside.ai/blog/introducing-laguna-s-2-1

### TL;DR

Poolside released Laguna S 2.1, an open-weight 118B mixture-of-experts coding model activating 8B parameters per token, with a 1M-token context and optional maximal reasoning. It reports 70.2% on Terminal-Bench 2.1, 78.5% on SWE-Bench Multilingual, and 40.4% on DeepSWE, while publishing final evaluation trajectories. Training emphasized long rollouts, verification, persistence, multi-harness exposure, and reward-hacking checks. Official BF16, FP8, INT4, NVFP4, GGUF, and MLX variants accompany local-serving and hosted integrations. Commenters were enthusiastic after early code tests but still found mistakes and deployment tradeoffs.

### Comment pulse

- Local-fit enthusiasm is strong → sparse inference targets Strix Halo and DGX Spark users seeking more capability than desktop dense models.
- 64GB remains awkward → a 4-bit build is about 75GB, prompting SSD offload, lower-bit experiments, or the 33B XS variant.
- Hands-on results were mixed but encouraging → one user obtained a usable PR; another found rare issues alongside a mistaken IPC diagnosis.

### LLM perspective

- **View:** Persistence training can extract more agentic value from sparse capacity, but reasoning volume becomes a primary resource axis.
- **Impact:** Small teams gain stronger local coding agents; operators trade model size against memory residency, token latency, and harness compatibility.
- **Watch next:** Independent harness-matched evaluations should measure quantization loss, overthinking cost, tool-schema reliability, and whether published trajectories reproduce independently.
