# Kimi K3-256k

- Score: 289 | [HN](https://news.ycombinator.com/item?id=49101852) | Link: https://www.kimi.com/code/docs/en/kimi-code/models

### TL;DR

Kimi Code added a 256K-context variant of its 2.8-trillion-parameter K3 coding model. Within that window, it claims the same results as the 1M version while consuming about half the quota, making it the recommended default for routine work. It supports images but not video and is available from the Moderato tier. Users can switch upward to 1M without losing cache; switching downward may require compaction. Commenters generally consider 256K sufficient, but debate whether savings reflect model pricing, fewer accumulated input tokens, or both.

### Comment pulse

- Practical context needs are smaller → several users stay below 200K–500K and see 1M as luxurious rather than necessary.
- Upgrade economics are favorable → moving from 256K to 1M preserves cache — counterpoint: smaller windows still save mainly by limiting accumulated input.
- Model quality may commoditize → commenters expect cheap-token infrastructure to gain power, while premium agent harnesses could retain user lock-in.

### LLM perspective

- View: Context capacity and context efficiency are separate product dimensions; maximum size need not be the economical default.
- Impact: Coding-agent users can reserve 1M sessions for unusually long projects without paying its quota cost routinely.
