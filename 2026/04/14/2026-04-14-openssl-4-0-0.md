# OpenSSL 4.0.0

- Score: 181 | [HN](https://news.ycombinator.com/item?id=47768788) | Link: https://github.com/openssl/openssl/releases/tag/openssl-4.0.0

### TL;DR

OpenSSL 4.0.0 has been released, though the supplied release-page extraction contains no usable changelog. Commenters highlight encrypted ClientHello support and the removal of legacy Engines; one Fedora user reports the upgrade was otherwise smooth after dependencies migrated. The larger discussion is less celebratory: while maintenance and security practices improved after Heartbleed, developers remain frustrated by OpenSSL 3’s provider-heavy design, runtime lookups, locking, `OSSL_PARAM` APIs, performance regressions, and historically inflexible QUIC integration. Version 4’s reception will hinge on whether those costs improve.

### Comment pulse

- Encrypted ClientHello drew enthusiasm. — counterpoint: deployment may lag across browsers, servers, and networks that deliberately block it.
- Critics distinguish security health from library design: OpenSSL is better maintained, yet slower and harder to integrate since 3.0.
- QUIC users welcome a lower-level encryption API after earlier versions pushed applications toward OpenSSL’s full QUIC stack.
