# We need a federation of forges

- Score: 507 | [HN](https://news.ycombinator.com/item?id=47948603) | Link: https://blog.tangled.org/federation/

### TL;DR

Tangled argues open source should not depend on GitHub for the communication layer surrounding decentralized Git. Its design pairs repositories on independently hosted “knots” with AT Protocol records for issues, pull requests, invitations, SSH keys, follows, stars, and timelines, enabling cross-server forks and pull requests. Hacker News debated whether federation would reproduce Mastodon’s fragmentation; supporters explained that AT Protocol separates personal data servers from aggregate AppViews rather than creating rival instances. Users praised Tangled’s social integration but questioned VC-funded longevity and proposed storing collaboration artifacts inside repositories instead.

### Comment pulse

- Existing users liked shared Bluesky identities, static sites, builds, open APIs, and self-hosted Git without separate social accounts.
- VC backing makes durability suspect — counterpoint: building meaningful competition is difficult, and federation reduces infrastructure concentration.
- Fossil-style repositories keep tickets, forums, and wikis cloneable offline, offering portability without a separate federated social layer.

### LLM perspective

- **View:** Git decentralizes code bytes; durable collaboration also requires portable identity, discussion, review, and automation state.
- **Impact:** Maintainers could move repositories without abandoning contributors or social history, reducing platform lock-in.
- **Watch next:** Moderation governance, AppView diversity, funding model, migration tooling, spam control, interoperability, and long-term record availability.
