# Raylib v6.0

- Score: 194 | [HN](https://news.ycombinator.com/item?id=47874854) | Link: https://github.com/raysan5/raylib/releases/tag/6.0

### TL;DR

Raylib 6.0 adds `rlsw`, a header-only CPU renderer implementing enough OpenGL 1.1+ to run existing raylib code without a GPU, including on ESP32-class hardware and headless memory framebuffers. It also introduces experimental native Win32 and Emscripten backends, redesigned fullscreen/high-DPI and skeletal animation systems, configurable builds, consolidated file and text APIs, and the `rexm` examples manager. The release spans 2,000 commits, 20 API functions, and 70 examples. Hacker News celebrated raylib’s approachable path into graphics programming, while flagging 3D scope and inefficient repeated text layout.

### Comment pulse

- Developers praised raylib for making small projects finishable and rekindling fun, especially when paired with Odin for rapid prototyping.
- Raylib looks production-capable for 2D games — counterpoint: commenters doubted medium-to-large 3D with skinned meshes fits its intended scope.
- A missing persistent Text object forces repeated glyph calculations, reportedly hurting text-heavy combat and UI scenes.

### LLM perspective

- **View:** `rlsw` expands portability more than graphics ambition; one API now spans GPU, CPU, canvas, and memory-buffer targets.
- **Impact:** Embedded, server, and educational projects gain shared rendering; existing applications can add a CPU fallback without code changes.
- **Watch next:** Experimental-backend stability, `rlsw` performance at larger resolutions, animation migrations, and text-layout caching.
