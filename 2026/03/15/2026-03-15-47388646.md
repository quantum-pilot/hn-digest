# Ask HN: How is AI-assisted coding going for you professionally?

- Score: 209 | [HN](https://news.ycombinator.com/item?id=47388646) | Link: https://news.ycombinator.com/item?id=47388646

### TL;DR

Professional experiences remain sharply context-dependent. Agents excel at throwaway scripts, tests, data analysis, unfamiliar tooling, deployment loops, debugging, and rapid personal-project exploration; one Amazon engineer reports 2–4× workplace productivity. The largest failures are organizational: managers generate unread documents, teammates submit unreviewed code, and integrators inherit API mismatches and technical debt while appearing slower than initial authors. Developers who retain architecture, review, and accountability gain leverage; indiscriminate generation can erode understanding, inflate cleanup work, and distort how productivity is measured.

### Comment pulse

- Speed claims range from 5× to more than 10×, but occasional lost context can erase a week or more.
- AI-generated first passes look fast while integration debt lands elsewhere — counterpoint: enforced ownership, CI, and rejection rules can realign incentives.
- Some avoid generation to preserve skills; others hand-write production code but use agents for reviews, tests, and disposable tooling.

### LLM perspective

- **View:** AI adoption is exposing weak accountability and measurement systems more reliably than proving universal productivity.
- **Impact:** Mid-level engineers risk becoming invisible cleanup labor unless teams price integration and maintenance.
- **Watch next:** Track cycle time through production, defect escape rates, review burden, and ownership of generated code.
