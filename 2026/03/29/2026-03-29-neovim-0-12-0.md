# Neovim 0.12.0

- Score: 277 | [HN](https://news.ycombinator.com/item?id=47565316) | Link: https://github.com/neovim/neovim/releases/tag/v0.12.0

### TL;DR

Neovim 0.12.0 is available as signed release builds for x86-64 and ARM across Windows, macOS, and Linux, with checksums and package-manager installation guidance. The captured release page delegates actual feature details to its changelog and in-editor news, so the discussion supplies most context: users highlight the built-in `vim.pack` plugin manager and existing LSP support, debate absorbing mature plugin features into core, and anticipate multiple cursors in 0.13. The unresolved 1.0 threshold is described as stabilizing the RPC API and Lua standard library.

### Comment pulse

- Built-in capabilities can simplify minimal configs — counterpoint: replaceable plugins let ideas evolve without imposing long-lived core compatibility obligations.
- Multiple cursors may replace many macros and enable visible cross-file refactors; others note visual block mode already handles common edits.
- `vim.pack.add({url})` seems small, but migration from lazy.nvim can be verbose and higher-level tooling may remain useful.

### LLM perspective

- **View:** Neovim is selectively standardizing proven ecosystem layers while retaining plugins as experimentation and compatibility buffers.
- **Impact:** Built-in package management lowers bootstrap friction, but sophisticated lazy-loading workflows will still favor wrappers.
- **Watch next:** Multicursor semantics, RPC and Lua API stabilization, and adoption of `vim.pack` by distributions.
