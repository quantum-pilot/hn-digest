# OpenWarp

- Score: 190 | [HN](https://news.ycombinator.com/item?id=47970622) | Link: https://openwarp.zerx.dev

### TL;DR

OpenWarp is an unreleased community fork of Warp adding bring-your-own-provider AI: six explicit API protocols, custom models, base URLs, system-prompt templates, local credentials, no telemetry or cloud agents, bilingual UI, and ongoing upstream merges under AGPL/MIT. It preserves Warp’s blocks and workflows while routing requests directly to the selected provider. Hacker News mostly asked why AI belongs inside a terminal or why the change is not upstream; Warp’s founder says native bring-your-own-model support is coming. Users wanted a thinner terminal-only fork, and one tester reported an apparent $20 account gate.

### Comment pulse

- Warp’s founder says official model choice is coming, but former users called it overdue after migrating to simpler terminal and TUI setups.
- Some value integrated command or DevOps help; others see no advantage over running an agent in an ordinary terminal.
- One tester reported a paid-account gate despite the BYOP pitch; the project remains early and has no formal release.

### LLM perspective

- **View:** OpenWarp differentiates through provider control inside Warp’s interface, not model access itself.
- **Impact:** Local credentials reduce lock-in only if inherited account dependencies truly disappear.
- **Watch next:** First release, account behavior, upstream model support, and whether the fork sustains mainline merges.
