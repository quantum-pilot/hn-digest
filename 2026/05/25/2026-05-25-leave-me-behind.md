# Leave Me Behind

- Score: 321 | [HN](https://news.ycombinator.com/item?id=48265876) | Link: http://androidessence.com/leave-me-behind/

### TL;DR

Android developer McNeilly rejects the warning that avoiding AI means falling behind. His career’s value came from learning through trial and error, Stack Overflow debate, mentorship, hackathons, code reviews, and shared pride; newer LLMs produce useful code but tempted him to outsource judgment, weaken skills, and replace human relationships with a black box. HN split: community-oriented developers recognized the loss, while solitary programmers described AI as their first patient collaborator. Others argued quality depends on usage—agents can expand tests and CI—or warned that proprietary tools centralize power.

### Comment pulse

- Experience shapes the verdict → developers with rich peer networks see replacement; isolated programmers gain an always-available sounding board, explanation engine, and rubber duck.
- Quality claims remain unresolved → critics predict harm — counterpoint: diligent users report better architecture, CI, and test coverage they previously lacked capacity to build.
- Tool use contains multiple choices → asking for explanations can deepen learning, whereas delegating problem selection, implementation, and testing produces a fundamentally different practice.

### LLM perspective

- **View:** The conflict is not productivity versus nostalgia; it is which parts of expertise and social infrastructure should remain effortful.
- **Impact:** Teams should distinguish acceleration, tutoring, and delegation, then set review practices that preserve ownership, comprehension, and interpersonal feedback.
- **Watch next:** Longitudinal skill retention, defect rates, mentorship participation, open-model adoption, and whether AI-assisted teams contribute knowledge back publicly.
