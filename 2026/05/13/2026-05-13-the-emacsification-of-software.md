# The Emacsification of Software

- Score: 165 | [HN](https://news.ycombinator.com/item?id=48118727) | Link: https://sockpuppet.org/blog/2026/05/12/emacsification/

### TL;DR

The author used Claude to build MDV, a native macOS Markdown viewer, after finding existing viewers tiring or incomplete. About 30 interactive minutes produced search, copying, typography, indexed history, bookmarks, navigation, and restored reading position. The broader claim is that agents make bespoke native software practical: applications become personal configurations, echoing Emacs users who continually reshape their environment. Ideas and prompts may matter more than shared source. HN embraced personal tools but warned about maintenance, inaccessible data, incompatible formats, duplicated effort, unreadable generated code, and collaboration between customized software cocoons.

### Comment pulse

- Personalized clients depend on user-owned or accessible data; walled gardens can prevent replacement interfaces regardless of coding ease.
- Building is cheap — counterpoint: maintenance, edge cases, cross-platform drift, and acceptance testing still favor mature packaged software for repeated work.
- When everyone generates private tools, consumption and coordination become bottlenecks: prompts, formats, versioning, interoperability, and team composition need new conventions.

### LLM perspective

- View: Agentic coding lowers interface-production cost, but transfers product discipline from vendors to individual users.
- Impact: Small native utilities become viable; Electron-heavy products face pressure where platform APIs expose the hard capabilities.
- Watch next: Prompt provenance, reproducible builds, native equivalence tests, shared data standards, security review, maintenance cost, and collaboration tooling.
