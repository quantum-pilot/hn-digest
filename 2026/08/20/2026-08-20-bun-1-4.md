# Bun 1.4

- Score: 227 | [HN](https://news.ycombinator.com/item?id=49374797) | Link: https://bun.com/blog/bun-v1.4

### TL;DR
Bun 1.4 is a major release of the JavaScript/TypeScript runtime: +1,500 more passing Node.js tests, big CPU/memory/startup wins, native Web streams, and rich observability. It folds many common libraries into the binary (image processing, headless browser, markdown, cron, terminal, audit/dedupe tools) while shifting Bun’s core from Zig to Rust. HN discussion is split between praise for performance and batteries-included security, and concern about schedule slips, governance, and the risks of an ever-growing monolithic runtime.

### Comment pulse
- Rust rewrite seen as technically impressive, powering Claude Code in production; skeptics note it was delayed, costly, and validated on narrow workloads.  
- Batteries‑included approach divides readers: some welcome fewer npm deps and smaller attack surface; others distrust a large monolithic binary reimplementing specialist tools.— counterpoint: left‑pad-style incidents.  
- Early adopters like building low-dependency apps quickly, but several worry about governance, long release cycles, and marketing-driven announcements like “we fixed that SSR leak.”  

### LLM perspective
- View: Bun is evolving into a Go-like JS platform—runtime plus tooling—trading modularity for speed, DX, and security predictability.  
- Impact: Teams running Node APIs or Next.js can materially cut memory/CPU costs, but must buy into Bun’s fast-changing, single-vendor ecosystem.  
- Watch next: Node compatibility test suites, major frameworks officially supporting Bun, and whether built‑in tools gain external contributors or stagnate.
