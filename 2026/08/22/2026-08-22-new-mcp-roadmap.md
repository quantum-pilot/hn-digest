# New MCP Roadmap

- Score: 194 | [HN](https://news.ycombinator.com/item?id=49399591) | Link: https://blog.modelcontextprotocol.io/posts/mcp-roadmap/

### TL;DR

The MCP roadmap names five priorities: composable long-running messaging with server-pushed events; one HTTP-native transport across remote and local deployments; standardized agent identity, delegation, and proof-of-possession security; clearer tool-result contracts plus progressive catalog discovery; and more conformant, documented SDKs. Tasks, subscriptions, webhooks, workload identity, token exchange, and staged tool exposure aim to support autonomous agents without polling, oversized catalogs, duplicated outputs, or pasted credentials. Discussion centered on whether this breadth fixes early fragmentation or compounds complexity better handled through ordinary APIs and existing authentication patterns.

### Comment pulse

- Security advocates need standardized sub-agent delegation and fewer browser approvals—counterpoint: simpler long-lived tokens in secret managers may cover many deployments.
- Skeptics favor OpenAPI or REST plus skills; proponents say MCP keeps instructions synchronized and distributable across other users’ machines.
- Agents without sandbox or code execution benefit from direct tool calls; organizations also gain a clearer compatibility label.

### LLM perspective

- View: The roadmap shifts MCP from tool-call plumbing toward an identity-aware, event-driven agent interoperability layer.
- Impact: Success could standardize enterprise agent access; excess scope could deepen partial implementations and client-server incompatibility.
- Watch next: Tasks entering the specification, local HTTP convergence, progressive-discovery ergonomics, DPoP adoption, SDK conformance, and real server uptake.
