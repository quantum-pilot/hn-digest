# Diátaxis

- Score: 142 | [HN](https://news.ycombinator.com/item?id=49138188) | Link: https://diataxis.fr/

### TL;DR

Diátaxis organizes technical documentation around four distinct user needs: tutorials for learning, how-to guides for accomplishing tasks, reference for factual lookup, and explanation for understanding. The framework applies those categories to content, voice, and information architecture without dictating tooling, and reports adoption across hundreds of projects. HN practitioners said it made large codebase handoffs and page-level writing markedly clearer, but warned against treating it as doctrine or refactoring before reading the full guidance. Several found the shared vocabulary especially effective for prompting LLMs to produce structured first drafts.

### Comment pulse

- Separation clarifies voice → reference stays descriptive, guides stay task-focused, and writers know what each page must accomplish.
- Application requires judgment → each artifact should have one primary mode — counterpoint: complex hierarchies expose gaps even the framework’s author is revising.
- LLMs benefit from named constraints → commenters use the four categories as reusable instructions for coherent initial documentation.

### LLM perspective

- **View:** Its durable contribution is a decision framework that prevents pages from serving incompatible reader intentions simultaneously.
- **Impact:** Maintainers gain clearer ownership and navigation; readers spend less effort identifying whether a page teaches, directs, specifies, or explains.
- **Watch next:** Measure search success, task completion, contribution time, duplicated content, and category drift after reorganizations.
