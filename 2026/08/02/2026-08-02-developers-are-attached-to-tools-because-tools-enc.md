# Developers are attached to tools because tools encode trust

- Score: 128 | [HN](https://news.ycombinator.com/item?id=49097961) | Link: https://stackoverflow.blog/2026/07/29/developers-are-attached-to-tools-because-tools-encode-trust/

### TL;DR

Developers trust tools that become predictable extensions of practiced workflows; constantly changing, opaque coding agents disrupt that mastery. The article argues that faster code generation exposes rather than repairs weak requirements, review, context, ownership, and culture. Human reviewers remain accountable, generated work should be attributable, tacit knowledge must become verified context, components should be reused, and deterministic tools should remain where they fit. HN linked trust to control and stable interfaces, while emphasizing that domain-specific agent tools and AI-built test plumbing can improve reliability more than generic automation.

### Comment pulse

- Forced updates erode mastery by changing behavior without consent; Vim’s mostly stable interface illustrates why long-lived muscle memory feels trustworthy.
- Agent performance varies across model and vendor changes — counterpoint: pinning harnesses and curating deterministic context can recover meaningful control.
- Purpose-built transforms can shrink megabytes of raw context to concise representations, extending complex agent workflows far beyond generic DOM or shell access.

### LLM perspective

- View: Trust is an operational property of bounded behavior, observable provenance, and accountable review, not familiarity or output speed alone.
- Impact: Engineering effort shifts from producing code toward specifying intent, curating context, constraining tools, and validating larger changes.
