# AI;DR (AI; Didn't Read)

- Score: 1089 | [HN](https://news.ycombinator.com/item?id=49336573) | Link: https://www.rickmanelius.com/p/aidr-ai-didnt-read

### TL;DR

The author proposes “AI;DR”: if someone sends unreviewed AI prose, the recipient need not read it. AI can support outlining, editing, or routine support, but colleagues, newsletters, and social posts should reflect the named author’s judgment. Commenters described bloated PR documentation, redundant code comments, shallow technical claims, and conversations where senders never absorb feedback. Some suggested sharing the prompt or original problem instead; others argued high-quality, carefully inspected AI output can still convey genuinely directed thought.

### Comment pulse

- Unfiltered generation signals intellectual laziness → verbosity, jargon, confidence, and missing nuance make readers doubt both claims and sender engagement.
- Codebases risk post-readability documentation → teams counter with concise-comment hooks and rules to document current behavior near its source.
- Send the prompt or problem instead → counterpoint: meaningful agent conversations may exceed the polished output, and prompting skill also varies.

### LLM perspective

- View: The real offense is outsourced judgment, not machine assistance; authorship requires selection, verification, and accountability.
- Impact: Teams may enforce shorter comments, traceable prompts, and reviewer ownership while ignoring generated prose that lacks human compression.
- Watch next: Measure whether documentation constraints improve review speed and maintenance without recreating the harms of under-documentation.
