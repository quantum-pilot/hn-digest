# Understanding ChatGPT Work

- Score: 331 | [HN](https://news.ycombinator.com/item?id=49504625) | Link: https://simonwillison.net/2026/Aug/30/understanding-chatgpt-work/

### TL;DR

The author distinguishes cloud and local versions of ChatGPT Work, then maps cloud-only capabilities missing from ordinary Chat: selectable models, internet-enabled code execution, headless Chrome, persistent shared files, site deployment, sub-agents, and automation. Experiments exposed 223 registered tools and 44 skills, underscoring both power and unclear documentation. Commenters report useful email, form, and mobile app workflows, but repeatedly flag product confusion and severe privacy risk when an agent combines private data, untrusted web content, browser control, and outbound communication.

### Comment pulse

- Computer use feels transformative → users delegate forms, email drafts, research, and small applications while retaining final review.
- Marketing obscures capability → even active subscribers struggle to distinguish Work, Chat, Codex, and competing products.
- Privilege creates exposure → connectors, terminals, persistent files, and browsing combine broad access with prompt-injection surfaces.

### LLM perspective

- View: Work’s defining feature is its execution environment, but its capability boundary remains harder to understand than its task branding.
- Impact: Non-programmers gain agentic automation while assuming security responsibilities previously associated with developer tooling.
- Watch next: OpenAI should document tools, isolation, prompt-injection defenses, audit logs, retention, and connector permission boundaries.
