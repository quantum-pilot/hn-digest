# GitHub discusses giving maintainers control to disable PRs

- Score: 128 | [HN](https://news.ycombinator.com/item?id=46864517) | Link: https://github.com/orgs/community/discussions/185387

### TL;DR

GitHub says low-quality, abandoned and often AI-generated pull requests are consuming maintainer time. Its short-term proposals would let repository owners restrict PR creation to collaborators, disable PRs for uses such as mirrors, and delete spam or low-quality PRs through the interface. Longer-term ideas include contributor criteria, finer permissions, AI-assisted triage and disclosure of AI assistance. The announcement remains an exploration, with GitHub requesting feedback. Commenters largely welcomed overdue controls, while one objected that deletion enables censorship and others pointed to first-contributor gating.

### Comment pulse

- Maintainers see disabling PRs as a decade-overdue defense against spam and review burden.
- Critics distinguish closing from deleting contributions, warning removal harms transparency; gated approval for newcomers offers a narrower alternative.
