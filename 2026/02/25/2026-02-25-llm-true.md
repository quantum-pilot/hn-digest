# LLM=True

- Score: 202 | [HN](https://news.ycombinator.com/item?id=47149151) | Link: https://blog.codemine.be/posts/2026/20260222-be-quiet/

### TL;DR

A developer argues that coding agents burn tokens and context on verbose command output, citing a TypeScript monorepo build that emitted roughly 1,005 words despite succeeding. Configuring Turbo and common environment flags reduced noise, while an agent’s habit of piping output through `tail` backfired on failures by hiding useful traces and triggering reruns. The proposed `LLM=true` environment variable would ask tools for concise, machine-oriented output, reducing cost and preserving context, though the same behavior could serve humans through standard quiet modes.

### Comment pulse

- Several commenters prefer wrappers that run commands once, preserve complete logs, and print a short result plus a path for later inspection.
- Some favor universal quiet or batch behavior for humans too; counterpoint: one `LLM=true` signal could replace scattered tool-specific settings.

### LLM perspective

- **View:** Structured, retrievable command output matters more than suppressing text indiscriminately.
- **Impact:** Cleaner logs can reduce reruns, token costs, and lost diagnostic context.
- **Watch next:** Whether toolchains converge on a generic machine-readable or agent-aware mode.
