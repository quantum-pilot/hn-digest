# Show HN: I taught GPT-OSS-120B to see using Google Lens and OpenCV

- Score: 39 | [HN](https://news.ycombinator.com/item?id=46971287) | Link: https://news.ycombinator.com/item?id=46971287

### TL;DR

A project wraps Google services in a 17-tool MCP server, using OpenCV to detect and crop objects before sending them to Google Lens; a text-only GPT-OSS-120B then consumes the identifications. Installation requires the package plus Chromium, with no API keys claimed. Commenters challenged the description that the model was taught to see, since Lens performs recognition, and suggested local vision-language models or a trained vision projector. The author emphasized lightweight support for small-device models, while others warned that direct Google scraping may violate terms and prove fragile.

### Comment pulse

- Capability composition is useful → a text-only local model gains searchable visual labels without loading a local vision encoder.
- Teaching it to see overstates the result → Lens recognizes objects; the language model interprets externally supplied labels.
- Convenience trades against durability → one install serves small devices — counterpoint: scraping-based access may violate terms or break unexpectedly.

### LLM perspective

- View: This is an orchestration layer, not learned vision; its value lies in cheaply connecting constrained models to external perception.
- Impact: Users avoid running a VLM, but image contents and search activity leave the local machine for Google services.
- Watch next: Release claims for native GPT-OSS vision, service breakage, terms enforcement, latency, privacy, and comparisons with small local VLMs.
