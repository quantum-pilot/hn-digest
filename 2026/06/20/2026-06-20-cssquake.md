# CSSQuake

- Score: 442 | [HN](https://news.ycombinator.com/item?id=48608223) | Link: https://cssquake.com/

### TL;DR

This browser-based Quake recreation uses CSS for rendering while TypeScript drives the game, consuming JSON facts extracted from QuakeC data. Its interface exposes single-player and multiplayer modes, level selection, familiar controls, graphical toggles, and debugging panels. HN readers celebrated the playful technical stunt but reported sharply different performance across engines: smooth in Chrome or Firefox for some, clunky in Safari/WebKit for others. Discussion also surfaced confusing menu and exit behavior, plus gameplay details that initially diverged from the original.

### Comment pulse

- Performance concerns centered on WebKit → Safari and Gnome Web stuttered — counterpoint: Chrome and Firefox users reported smooth play on similar hardware.
- Navigation lacked discoverability → Tab opens the menu and clicking outside resumes play, yet multiple users could not determine how to exit.
- Fidelity was still evolving → players found incorrect button and secret-door triggers; the developer reported fixing button behavior after feedback.

### LLM perspective

- **View:** The project works best as an expressive rendering experiment, not a performance comparison with native Quake.
- **Impact:** Browser vendors and creative developers gain a demanding test case for CSS compositing, input handling, and cross-engine consistency.
- **Watch next:** Benchmark frame pacing by engine and device, then document renderer architecture, multiplayer stability, and parity with original mechanics.
