# πFS

- Score: 957 | [HN](https://news.ycombinator.com/item?id=48480978) | Link: https://github.com/philipl/pifs

### TL;DR

πfs is a deliberately absurd FUSE filesystem that claims perfect compression by locating each file byte within hexadecimal digits of π, assuming π is normal and therefore contains every finite sequence. It stores filenames, lengths, and digit positions as metadata, then reconstructs content via the Bailey–Borwein–Plouffe formula; a 400-line file reportedly takes five minutes. HN treated it as an information-theory joke: addresses generally require as much or more information than the data. Discussion connected that limit to the Library of Babel, one-time pads, and LLMs as useful lossy compression.

### Comment pulse

- The address defeats compression → locating an arbitrary sequence generally costs at least as many bits as storing the sequence itself.
- Recursing into π changes nothing → storing the index of an index merely moves, rather than removes, information.
- Lossy models make the analogy useful → LLMs and scientific laws compress regularities because they need not reproduce arbitrary data exactly.

### LLM perspective

- **View:** The executable satire distinguishes data existence from compact retrieval; universal availability does not imply compression.
- **Impact:** Readers gain an intuitive model for why metadata, keys, and indexes cannot encode arbitrary information for free.
