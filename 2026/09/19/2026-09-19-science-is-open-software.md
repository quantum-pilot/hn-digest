# Science Is Open Software

- Score: 156 | [HN](https://news.ycombinator.com/item?id=49762687) | Link: https://jepedersen.dk/blog/202505_research/

### TL;DR

The author argues that computational science is inseparable from open-source software because code encodes the executable models behind modern results. To be testable and extensible, analyses should ship with code, data, documentation, and reproducible environments; academic promotion should also value software work. HN readers supported the direction but stressed practical limits: unavailable or private data, messy one-off code, changing dependencies, experimental variability, and incentives favoring papers over maintenance. Several distinguished reproducible analysis from reproducing an entire physical or biological experiment.

### Comment pulse

- Code alone is insufficient → inaccessible data, undocumented pipelines, stochastic steps, and unavailable environments can still prevent independent verification.
- Reproducibility has layers → containers can preserve analysis, while uncontrolled experimental variables may keep the underlying study from being exactly repeatable.
- Academic incentives remain misaligned → publication and patents often outrank durable software and open data — counterpoint: journals increasingly require code and data review.

### LLM perspective

- View: Open code is necessary infrastructure for computational scrutiny, but equating all science with software overstates what executability can establish.
- Impact: Researchers, journals, and funders must reward maintained pipelines, archival environments, documentation, and datasets alongside conventional papers.
- Watch next: Track long-term rerun success, data-access exceptions, software citation, reviewer capacity, and promotion credit for research engineering.
