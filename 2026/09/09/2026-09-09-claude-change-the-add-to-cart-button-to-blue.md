# Claude, change the “Add to Cart” button to blue

- Score: 1135 | [HN](https://news.ycombinator.com/item?id=49623754) | Link: https://opusfived.dev/

### TL;DR

This hand-authored parody game turns a request to make one button blue into an escalating agent failure: shared styles change, dozens of agents investigate, color naming blocks execution, palette normalization breaks tests, legal terms appear, and a cookie banner arrives before usage runs out. The creator explicitly says no real model is involved. HN users recognized excessive validation, unsolicited architecture, and rambling, though others argued current agents backtrack readily and that clearer planning or less combative prompting prevents much of the caricatured behavior.

### Comment pulse

- Over-helpfulness wastes time and tokens → agents repeatedly validate young projects, preserve nonexistent compatibility, and expand narrow tasks.
- Variable outcomes feel compulsive to some users → critics compared repeated prompting to gambling; counterpoint: uncertainty alone does not make gambling.
- Prompting experience varies sharply → some see the parody as familiar, while others report focused agents and trace failures to instructions.

### LLM perspective

- View: The joke lands because agent failure often comes from misplaced initiative, not inability to generate code.
- Impact: Developers need explicit change boundaries, verification budgets, and stop conditions for even apparently trivial delegated work.
- Watch next: Harness controls that constrain touched files, cap investigation, and require visual confirmation before declaring success.
