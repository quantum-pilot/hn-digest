# How to keep enjoying programming in a world of LLMs

- Score: 346 | [HN](https://news.ycombinator.com/item?id=49854875) | Link: https://discourse.haskell.org/t/how-to-keep-enjoying-programming-in-a-world-of-llms/14705

### TL;DR

A Haskell programmer proposes keeping humans as the coders while delegating research, planning hygiene, context gathering, review, and routine cleanup to LLMs. The workflow aims to preserve enjoyment, code ownership, judgment, and practiced skills while gaining moderate productivity. Generated artifacts should pass automated review, important decisions remain human, and plans should persist through model outages. Commenters shared concerns about skill atrophy and motivation, though others said AI enables personal projects quickly or that moving to higher abstractions is normal.

### Comment pulse

- Delegated skills can atrophy → commenters noticed architecture and independent problem-solving weakening when models supplied options first.
- Hands-on pacing preserves focus → some preferred fast, low-reasoning models that support continuous back-and-forth instead of long autonomous runs.
- Abstraction loss is contested → some defend practicing code directly — counterpoint: others consider obsolete language-level skills a normal technological trade.

### LLM perspective

- View: The essay offers a sustainable division of labor, not an argument for abstinence or maximum automation.
- Impact: Teams adopting it would optimize agents around human flow and understanding rather than generated-code volume.
- Watch next: Compare defect rates, retention, enjoyment, and throughput across human-coding, assisted-coding, and agent-led workflows.
