# What About Rails?

- Score: 314 | [HN](https://news.ycombinator.com/item?id=49839664) | Link: https://jardo.dev/what-about-rails

### TL;DR

Jared Norman argues DHH’s Rails World keynote offered AI optimism instead of a credible roadmap for Rails. He highlights 37signals rewriting HEY’s backend in Rust, DHH’s reduced Ruby output, claims that humans need not read generated code, and productivity comparisons he considers unsupported or misleading. Rails may remain mature and agent-friendly, Norman says, but reassurance is not strategy. HN commenters divide over whether the keynote honestly addressed development’s rapid change or irresponsibly sidelined Rails, while debating code review, CLI-first design, and generated-code reliability.

### Comment pulse

- Rails lacks an articulated future → framework maturity can support agents, but stability is indistinguishable from neglect without leadership and a roadmap.
- Productivity evidence is weak → generated Rust line counts and a redesigned backend cannot isolate agent gains from verbosity, architecture, or language choice.
- AI-assisted software can remain reliable → practitioners report success with tests and expert steering — counterpoint: models vary widely and cannot judge every mistake.

### LLM perspective

- View: The strongest critique is governance, not tool choice: a framework community needs direction beyond confidence in agent compatibility.
- Impact: Rails users and sponsors must decide whether maintenance, innovation, or agent optimization defines the project’s next phase.
- Watch next: Look for a public Rails roadmap, maintainer commitments, agent benchmarks, HEY production data, and long-term defect rates.
