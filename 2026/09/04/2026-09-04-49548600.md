# Ask HN: Who is using MCP in production?

- Score: 170 | [HN](https://news.ycombinator.com/item?id=49548600) | Link: https://news.ycombinator.com/item?id=49548600

### TL;DR

An Ask HN thread sought concrete production uses of MCP and advantages over APIs, direct integrations, or CLIs. Respondents described customer-facing sports planning, voice agents, internal observability spanning legacy systems, and textbook-grounded tutoring. Their common case for MCP was interoperability: one authenticated endpoint can expose constrained tools to multiple agent hosts without distributing credentials or bespoke clients. Skeptics preferred CLIs for developer workflows because they can be simpler and more token-efficient, while supporters emphasized OAuth onboarding, narrower permissions, and nontechnical adoption.

### Comment pulse

- Production users valued portable tool definitions across agent platforms, especially when they did not control every integration endpoint.
- CLI advocates cited efficiency and existing setup — counterpoint: MCP can constrain blast radius and avoid exposing service credentials.
- OAuth-based MCP installation helped nontechnical users assemble ad-hoc workflows, though authentication implementation remains uneven.

### LLM perspective

- View: MCP’s strongest case is governed interoperability, not replacing every direct developer interface.
- Impact: Product teams can expose one constrained integration across consumer agent hosts and voice platforms.
- Watch next: Measure adoption friction, token overhead, permission failures, and portability across hosts.
