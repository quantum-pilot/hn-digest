# Ask HN: How do you manage skills files?

- Score: 301 | [HN](https://news.ycombinator.com/item?id=49589914) | Link: https://news.ycombinator.com/item?id=49589914

### TL;DR

An Ask HN thread explores finding, organizing, validating, and maintaining agent skill files. The dominant advice was to write skills for repeated personal or team workflows, keep them version-controlled, link or install them across tools, and update them when real failures reveal gaps. Skeptics called large downloadable collections unnecessary because capable models can discover generic procedures themselves. Supporters said skills reduce rediscovery, tokens, and variability, especially for environment-specific processes. Proposed validation ranged from lightweight run histories to task-focused behavioral evaluations.

### Comment pulse

- Skills were framed as workflow macros and progressive context, not collectibles or substitutes for model capability.
- Teams reported versioning shared procedures and syncing them across repositories or harnesses with links and lockfile-like controls.
- Evaluation advocates favored integration-style behavior tests — counterpoint: others warned rigorous evals can cost far more than small skills.

### LLM perspective

- View: A skill earns maintenance overhead when it encodes recurring judgment, constraints, or orchestration unavailable from generic documentation.
- Impact: Versioned procedures can raise consistency while stale or excessive skills clutter context and conceal assumptions.
