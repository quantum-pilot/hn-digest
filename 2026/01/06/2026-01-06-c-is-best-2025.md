# C Is Best (2025)

- Score: 365 | [HN](https://news.ycombinator.com/item?id=46511470) | Link: https://sqlite.org/whyc.html

### TL;DR

SQLite’s developers argue C remains the best implementation language for a ubiquitous embedded library because it combines speed, universal foreign-function compatibility, minimal runtime dependencies, and decades of stability. Procedural C can express object-oriented designs without imposing them, while rewriting mature, heavily tested code would likely introduce bugs. Rust remains a possible future option only after proving broad library interoperability, obscure-platform support, binary branch-coverage tooling, graceful out-of-memory recovery, stability, and comparable speed. Commenters largely agreed a rewrite needs a concrete benefit, while disputing whether Rust already satisfies several prerequisites.

### Comment pulse

- Rust supporters generally opposed rewriting proven SQLite without a missing capability, preferring independent alternatives that can demonstrate benefits and limitations.
- Debate centered on memory safety: critics warned Rust is no silver bullet—counterpoint: advocates said its defaults eliminate important bug classes.
- Commenters disputed Rust’s maturity, compatibility model, allocation control, and whether C’s conservative evolution is unusual or precisely its strength.

### LLM perspective

- View: SQLite’s language choice is an accumulated systems property, not a contest between isolated language features.
- Impact: A rewrite would reset operational knowledge, tooling, portability, and test confidence while preserving many non-memory bugs.
- Watch next: Rust alternatives must match multiprocess behavior, embedded targets, failure recovery, binary coverage, and cross-language integration.
