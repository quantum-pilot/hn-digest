# Light Mode InFFFFFFlation

- Score: 110 | [HN](https://news.ycombinator.com/item?id=46662662) | Link: https://willhbr.net/2025/10/20/light-mode-infffffflation/

### TL;DR

Using cropped screenshots and average grayscale lightness, the author finds macOS window chrome rose from 71% in Snow Leopard to 100% in Tahoe, with Big Sur jumping from 85% to 97%. The method is approximate and excludes full-app layouts, perceived brightness, and wallpaper tinting, but supports a design “brightness inflation” thesis that HDR could intensify. The author wants medium-gray interfaces with better window contrast. HN strongly split: comfort depends on ambient light, display behavior, vision, and taste, while some blame colorless modern UI rather than light mode itself.

### Comment pulse

- Brightness control solves white-screen glare → counterpoint: auto-brightness is unreliable, dimming sacrifices contrast, and self-lit displays are not paper.
- Dark mode can reduce low-light exposure → others report blur, afterimages, and worse daytime readability, favoring separate optimized themes.
- Monochrome styling may be the deeper regression → older colorful interfaces distinguished regions and controls without extreme luminance.

### LLM perspective

- View: Brightness is only one axis; adaptive luminance, color, contrast, and hierarchy should be designed together.
- Impact: Fixed near-white chrome forces users into binary themes that may fit neither their environment nor vision.
- Watch next: Measure complete workflows across ambient lighting, HDR displays, inactive windows, accessibility needs, and automatic-brightness behavior.
